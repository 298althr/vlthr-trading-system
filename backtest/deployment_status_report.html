Bugs Fixed

1. V2 RSI Momentum Filter Blocked Mean Reversion Signals (CRITICAL)

The RSI momentum filter rejected SHORT signals when RSI was rising and LONG signals when RSI was falling. This is correct for trend_following but wrong for mean_reversion, where rising RSI into overbought IS the SHORT entry signal and falling RSI into oversold IS the LONG entry signal. This blocked all mean_reversion trades for XRP, ETH, and BNB.

Fix: Wrapped the RSI momentum check in if strategy == "trend_following": so mean_reversion signals bypass it.

pipeline/engine/v2_filters.py:221-226

2. ETH rsi_oversold=0 Prevented LONG Entries (MAJOR)

ETH config had rsi_oversold set to 0. The adaptive scorer checks rsi_oversold > 0 before allowing oversold LONG entries. With 0, ETH could only go SHORT when RSI reached overbought (65+). LONG entries via oversold condition were impossible.

Fix: Changed rsi_oversold from 0 to 35, consistent with other mean_reversion symbols (XRP=30, BNB=30).

pipeline/engine/portfolio_config.py:24

3. DQ Freshness Threshold Too Strict for 15m Bars (MAJOR)

The Data Quality Gate freshness scoring used a 15-minute threshold. Since enriched data uses 15m bars, the latest bar can naturally be 15+ minutes old before the next bar closes. With enrichment cycle lag (30+ min to process all symbols), freshness dropped to 0, blocking all signals.

Fix: Increased freshness threshold from 15 to 45 minutes (3x the 15m bar interval).

pipeline/engine/portfolio_orchestrator.py:115

4. Pre-flight bar_max_age_min Too Strict (MAJOR)

The safety layer pre-flight check used bar_max_age_min=10 on 1m data. Data ingestion cycles through 6 symbols and some get quarantined by validation, causing 10+ minute delays. This aborted pipeline iterations before they could scan.

Fix: Increased bar_max_age_min from 10 to 20 minutes.

pipeline/engine/portfolio_config.py:181
