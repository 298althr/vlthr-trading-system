Root Causes
  1. Glassmorphism everywhere. backdrop-filter: blur(20px) saturate(1.4) on 23 elements. Each creates a GPU layer. Mobile devices render this at 2-5x normal cost.
  2. 2,494 lines of CSS. One file. Duplicate rules, unused selectors, 6 gradient layers, 14 keyframe animations.
  3. No code splitting. All 7 pages imported eagerly in App.tsx. User loads 5,902 lines of TS to view one tab.
  4. No virtualization. Signal lists and trade tables render all rows. 50+ DOM nodes per signal card.
  5. SSE over-fetching. Every 5-minute update replaces all state. No diffing, no pagination.
Feature Engineering Gap

The system collects 6 data types but only computes features on OHLCV (7 indicators: RSI, ATR, ADX, EMA fast/slow/200, BB, VWAP, log return). The other 5 data types (funding, OI, orderbook, LS ratio, enriched) have no engineered features exposed to the frontend. The model state table stores checkpoints but no feature importance or prediction confidence is surfaced to the user.

The 500% Problem
The frontend uses 5x the planned compute because glassmorphism creates GPU layers on every surface. A $5/month VPS cannot sustain 50+ concurrent GPU-blur layers. The fix is architectural: remove all backdrop-filter, cut CSS to 300 lines, lazy-load pages, and use flat surfaces with one accent color.

Feature Engineering Schema

One engineered feature per ingestion table, plus model state. Each feature is computed by the ai-trader-engine and stored in a new feature_store PostgreSQL table. The frontend reads and manages these via a new Feature Manager page.

New Table: feature_store
CREATE TABLE IF NOT EXISTS feature_store (
    id              BIGSERIAL PRIMARY KEY,
    run_time        TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    symbol          VARCHAR(16) NOT NULL,
    data_source     VARCHAR(32) NOT NULL,    -- ohlcv | funding | open_interest | orderbook | ls_ratio | model
    feature_name    VARCHAR(64) NOT NULL,    -- e.g. 'funding_zscore', 'oi_momentum', 'ob_imbalance'
    feature_value   DOUBLE PRECISION,
    feature_metadata JSONB,                  -- extra context (lookback, threshold, etc.)
    is_enabled      BOOLEAN DEFAULT TRUE,    -- frontend can toggle on/off
    created_at      TIMESTAMPTZ DEFAULT NOW()
);

CREATE INDEX idx_feature_store_source ON feature_store(data_source);
CREATE INDEX idx_feature_store_symbol  ON feature_store(symbol, run_time DESC);
CREATE INDEX idx_feature_store_enabled ON feature_store(is_enabled) WHERE is_enabled = TRUE;
Feature Definitions (one per table)
Data SourceFeature NameFormulaLookbackPurpose
OHLCV price_momentum (close[-1] - close[-N]) / close[-N] * 100 N = 20 bars Detect trend direction strength. Already partially computed as log_ret but not exposed live.
Funding rate funding_zscore (current - mean_30d) / std_30d 30 days Detect extreme funding (squeeze risk). Z > 2 = extreme. Drives crowding detection.
Open interest oi_momentum (oi[-1] - oi[-6]) / oi[-6] * 100 6 bars (30 min on 5m) Rising OI + rising price = new longs. Falling OI + rising price = short squeeze. Already raw value in enriched, but no rate-of-change feature.
Orderbook L2 ob_imbalance_ratio sum(bid_size L1-L5) / (sum(bid_size) + sum(ask_size)) Snapshot (latest) Buy/sell pressure from top 5 levels. > 0.6 = bid-heavy. Already computed as ob_imbalance_pct in signals, but not as a standalone feature.
LS ratio ls_ratio_shift buyRatio[-1] - buyRatio[-6] 6 bars Change in trader positioning. Positive shift = traders going long. Contrarian signal when extreme.
Model state model_confidence 1 - brier_score (from predictions table) Rolling 50 predictions Online ML model health. Confidence < 0.55 = model in shadow, do not trust predictions. Already tracked in pipeline_brain.py but not exposed.
New Table: feature_config

Frontend-managed configuration for each feature. User can enable/disable, adjust lookback, set thresholds.

CREATE TABLE IF NOT EXISTS feature_config (
    id              SERIAL PRIMARY KEY,
    data_source     VARCHAR(32) NOT NULL UNIQUE,
    feature_name    VARCHAR(64) NOT NULL,
    is_enabled      BOOLEAN DEFAULT TRUE,
    lookback_bars   INTEGER DEFAULT 20,
    threshold_high  DOUBLE PRECISION,       -- alert threshold
    threshold_low   DOUBLE PRECISION,
    description     TEXT,
    updated_at      TIMESTAMPTZ DEFAULT NOW()
);

Seed data: one row per data source with defaults from the table above.

Why One Feature Per Table
Starting with one engineered feature per data source proves the pipeline end-to-end. Once the schema, API, and UI are working, adding more features per table is a config insert, not an architecture change.

Backend API Changes

Three new endpoint groups: feature compute (ai-trader-engine), feature read/write (backend), and SSE feature stream.

SSE: New Event Type

Add a features event to the existing SSE stream. Fired when pipeline computes new features.

// In backend/src/server.cjs SSE handler:
// After pipeline update, also fetch latest features
const features = await pool.query(
  'SELECT symbol, data_source, feature_name, feature_value, feature_metadata FROM feature_store WHERE is_enabled = TRUE AND run_time > NOW() - INTERVAL \'10 minutes\' ORDER BY run_time DESC'
);
broadcast({ type: 'features', features: features.rows });

New Page: Feature Manager

A new FeaturesPage.tsx tab. Shows a table of all 6 data sources with their engineered feature. User can:

  • View latest value per symbol per feature
  • Toggle on/off via a button (calls /api/features/toggle)
  • Adjust lookback via a number input (calls /api/features/config PUT)
  • Set thresholds for high/low alerts
  • See sparkline of last 50 values (inline SVG, no chart library)

Component target: 120 lines. No chart library. Sparkline is a 60-line inline SVG component.

Abstract Background (optional, zero compute)

For visual identity without GPU cost: use a single static SVG pattern as a CSS background-image on the body. No blur, no animation.

body {
  background-color: #000;
  background-image: url('data:image/svg+xml,...');  /* 200 byte grid pattern */
  background-size: 40px 40px;
  /* Total cost: 1 paint, 0 GPU layers */
}
Button Component (TypeScript)
// components/Button.tsx — 30 lines, one component
import { ButtonHTMLAttributes } from 'react';

interface Props extends ButtonHTMLAttributes<HTMLButtonElement> {
  variant?: 'primary' | 'ghost';
  size?: 'sm' | 'md';
}

export function Button({ variant = 'primary', size = 'md', ...props }: Props) {
  return (
    <button
      {...props}
      style={{
        padding: size === 'sm' ? '6px 12px' : '10px 20px',
        background: variant === 'primary' ? '#e82127' : 'transparent',
        color: variant === 'primary' ? '#fff' : '#e8e8e8',
        border: '1px solid #222',
        borderRadius: 8,
        cursor: 'pointer',
        fontSize: 14,
        ...props.style,
      }}
    />
  );
}

No CSS class. Inline styles for components. CSS file only for layout (flex, grid, spacing). This keeps the CSS file under 300 lines.
