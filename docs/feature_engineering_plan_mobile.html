Root Causes⚡
  1. Glassmorphism everywhere. backdrop-filter: blur(20px) on 23 elements. Each creates a GPU layer.
  2. One 2,494-line CSS file. Duplicate rules, unused selectors, 6 gradient layers.
  3. No code splitting. All 7 pages load eagerly.
  4. No virtualization. Signal lists render all rows.
  5. SSE over-fetching. Every 5-minute update replaces all state.
The 500% Problem

The frontend uses 5x planned compute because glassmorphism creates GPU layers on every surface. The fix is architectural. Remove all backdrop-filter, cut CSS to 300 lines, lazy-load pages, and use flat surfaces with one accent color.

Architecture

Feature Schema

One engineered feature per ingestion table, plus model state. Each feature is computed by the ai-trader-engine and stored in a new feature_store PostgreSQL table.

New Table: feature_storeSQL
CREATE TABLE IF NOT EXISTS feature_store (
    id              BIGSERIAL PRIMARY KEY,
    run_time        TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    symbol          VARCHAR(16) NOT NULL,
    data_source     VARCHAR(32) NOT NULL,
    feature_name    VARCHAR(64) NOT NULL,
    feature_value   DOUBLE PRECISION,
    feature_metadata JSONB,
    is_enabled      BOOLEAN DEFAULT TRUE,
    created_at      TIMESTAMPTZ DEFAULT NOW()
);

CREATE INDEX idx_feature_store_source
    ON feature_store(data_source);
CREATE INDEX idx_feature_store_symbol
    ON feature_store(symbol, run_time DESC);
CREATE INDEX idx_feature_store_enabled
    ON feature_store(is_enabled) WHERE is_enabled = TRUE;

OHLCV: price_momentum

Formula: (close[-1] - close[-N]) / close[-N] * 100

Purpose: Detect trend direction strength. Already partially computed as log_ret but not exposed live.

Funding: funding_zscore

Formula: (current - mean_30d) / std_30d

Purpose: Detect extreme funding (squeeze risk). Z > 2 = extreme. Drives crowding detection.

Open Interest: oi_momentum

Formula: (oi[-1] - oi[-6]) / oi[-6] * 100

Purpose: Rising OI + rising price = new longs. Falling OI + rising price = short squeeze.

Orderbook: ob_imbalance_ratio

Formula: sum(bid_size L1-L5) / (sum(bid_size) + sum(ask_size))

Purpose: Buy/sell pressure from top 5 levels. > 0.6 = bid-heavy.

LS Ratio: ls_ratio_shift

Formula: buyRatio[-1] - buyRatio[-6]

Purpose: Change in trader positioning. Positive shift = traders going long. Contrarian signal when extreme.

Model: model_confidence

Formula: 1 - brier_score from predictions table

Purpose: Online ML model health. Confidence < 0.55 = model in shadow, do not trust predictions.

New Table: feature_configConfig

Frontend-managed configuration for each feature. Enable/disable, adjust lookback, set thresholds.

CREATE TABLE IF NOT EXISTS feature_config (
    id              SERIAL PRIMARY KEY,
    data_source     VARCHAR(32) NOT NULL UNIQUE,
    feature_name    VARCHAR(64) NOT NULL,
    is_enabled      BOOLEAN DEFAULT TRUE,
    lookback_bars   INTEGER DEFAULT 20,
    threshold_high  DOUBLE PRECISION,
    threshold_low   DOUBLE PRECISION,
    description     TEXT,
    updated_at      TIMESTAMPTZ DEFAULT NOW()
);

Seed data: one row per data source with defaults from the table above.

Why One Feature Per Table

Starting with one engineered feature per data source proves the pipeline end-to-end. Adding more features per table later is a config insert, not an architecture change.

Interface

Backend API

Three new endpoint groups: feature compute in ai-trader-engine, feature read/write in backend, and SSE feature stream.

ai-trader-engineFastAPI
EndpointMethod
/features/computePOST
/features/compute/allPOST
/features/historyGET

/features/compute computes all enabled features for a symbol. Body: { symbol, data_sources? }.

/features/compute/all computes for all symbols. Called by pipeline on each run.

/features/history returns feature history. Query: symbol, data_source, limit.

backendExpress
EndpointMethod
/api/features/latestGET
/api/features/configGET / PUT
/api/features/togglePOST
/api/features/history/:symbol/:sourceGET

/api/features/latest returns latest values for all symbols.

/api/features/config reads or updates config rows.

/api/features/toggle enables or disables a feature.

/api/features/history/:symbol/:source returns sparkline data. Query: limit=50.

SSE Event TypeStream

Add a features event to the existing SSE stream. Fired when pipeline computes new features.

// backend/src/server.cjs SSE handler
const features = await pool.query(
  `SELECT symbol, data_source, feature_name,
          feature_value, feature_metadata
   FROM feature_store
   WHERE is_enabled = TRUE
     AND run_time > NOW() - INTERVAL '10 minutes'
   ORDER BY run_time DESC`
);
broadcast({ type: 'features', features: features.rows });

  • Toggle on/off via a button
  • Adjust lookback via a number input

import { ButtonHTMLAttributes } from 'react';

interface Props extends ButtonHTMLAttributes<HTMLButtonElement> {
  variant?: 'primary' | 'ghost';
  size?: 'sm' | 'md';
}

export function Button({ variant = 'primary', size = 'md', ...props }: Props) {
  return (
    <button
      {...props}
      style={{
        padding: size === 'sm' ? '6px 12px' : '10px 20px',
        background: variant === 'primary' ? '#e82127' : 'transparent',
        color: variant === 'primary' ? '#fff' : '#e8e8e8',
        border: '1px solid #222',
        borderRadius: 8,
        cursor: 'pointer',
        fontSize: 14,
        ...props.style,
      }}
    />
  );
}

Inline styles for components. CSS file only for layout.
