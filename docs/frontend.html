Overview

The frontend is a React 19 single-page application built with Vite 8 and served by nginx. It connects to the backend Express server via SSE for real-time signal updates and REST API for trade management. The app is a PWA with service worker support for mobile installation.

Key Features
  • Real-time SSE: Live signal feed via EventSource at /api/signals/stream
  • Auto-execute: Toggle to auto-open paper trades for EXCELLENT signals (confidence >= 65, age < 120 min)
  • Live price ticker: Marquee strip with 24h change for all tracked symbols
  • PWA: Service worker for offline shell, push notifications on iOS and Android
  • Session auth: 1-hour session with localStorage persistence
  • Backtest UI: D1-D7 pipeline runner with AI chat panel and results visualization
Docker Service
Runs as vlthr-dashboard-frontend container. Multi-stage build: node:22-slim compiles the SPA, nginx:alpine serves the static files. Port 5175 maps to container port 80. Depends on backend service.

Pages

The app has 5 main pages accessible via bottom navigation. Each page is a React component in frontend/src/pages/.

Dashboard DASH

DashboardPage.tsx (19 KB). Main landing page. Shows active signal cards, paper trading account summary, live price ticker, VTC token stats, and AI overview generator.

  • Signal cards: One per active signal with DQS, confidence, entry/SL/TP, RSI, ADX, funding
  • Account summary: Balance, equity, open risk, active trades count
  • AI Overview: Calls /api/overview/generate to produce a natural language market summary
  • Sparkline charts: Mini price charts per symbol
Signals SIGNALS

SignalsPage.tsx (4 KB). Lists all active signals with search filter. Shows watchlist items with gate status (session, ADX, direction, RSI, bull). Click a signal to open paper trade modal.

VTC VTC

VTCPage.tsx (21 KB). Performance-weighted token dashboard. Shows VTC price, score vector, history chart, treasury stats, and audit log. Mint and burn operations.

Backtest BACKTEST

BacktestPage.tsx (7 KB). D1-D7 pipeline runner. Three sub-tabs: config, chat, results.

  • Config: Select symbol, timeframe, date range, stages to run
  • Chat: AI chat panel (AiChatPanel.tsx, 37 KB) with NVIDIA LLM integration via backend proxy
  • Results: Stage-by-stage results with metrics (Sharpe, PF, WR, max DD, Sortino)
  • Session persistence: Backtest sessions saved to localStorage via Zustand store
Paper PAPER

PaperPage.tsx (42 KB). Paper trading account management. Three sections: pending, active, closed trades.

  • Account: Balance, equity, margin, PnL
  • Pending trades: Signals waiting for entry confirmation
  • Active trades: Open positions with live PnL, dynamic SL status, time in trade
  • Closed trades: History with exit reason, PnL, duration
  • Winners: Best performing closed trades leaderboard

SSE Data Flow

The frontend receives all real-time data via a single Server-Sent Events connection to /api/signals/stream. The useSSE hook manages the connection lifecycle.

SSE Event Types
EventTriggerPayload
initialOn connectFull state: signals, watchlist, powerTrades, winners, history, paper, livePrices, marketIntel, vtc
updateEvery pipeline run (5 min)Same as initial. Replaces all state.
pricesEvery 15 secondslivePrices: { symbol: { price, change24h } }
intelOn market intel refreshmarketIntel: { symbol: { rsi, adx, funding, oi, ... } }
refreshProgressDuring data refresh{ step, total, message }
refreshCompleteRefresh finishedTriggers full state re-fetch
Connection Lifecycle
  1. App mounts, useSSE hook fires
  2. Connects to {API_BASE}/api/signals/stream via EventSource
  3. Receives initial event with full state snapshot
  4. Listens for update events (every 5 min from pipeline)
  5. Listens for prices events (every 15s from backend)
  6. On error: closes connection, waits with exponential backoff (1s, 2s, 4s, ... 30s max), reconnects
  7. On successful reconnect: resets backoff to 1s
Push Notifications

The hook sends browser notifications for two events:

  • New pending trade: Fires when a new signal enters pending state
  • Trade closed: Fires when an active trade closes (TP hit, SL hit, or manual)

Uses dual-path notification delivery: legacy Notification constructor for desktop, service worker showNotification for iOS PWA and Android.

Auto-Execute Logic

When auto-execute is toggled on, the app monitors SSE signals and auto-opens paper trades for qualifying signals:

  • Signal strength: EXCELLENT
  • Confidence: >= 65
  • Age: < 120 minutes
  • Lifecycle: Not CANCELED or ABANDONED
  • Dedup: Uses a ref Set to prevent duplicate executions

Sends POST to /api/paper/trade with signalId, symbol, side, entryPrice, qty, leverage, riskPercent.

API Integration

The frontend talks to two backend services. In production (Docker), nginx proxies /api/ to the backend container. The backend then proxies AI engine requests to the ai-trader-engine container.

Configuration
// frontend/src/config.ts
export const API_BASE = import.meta.env.VITE_API_BASE
  ?? (import.meta.env.PROD ? '' : 'http://localhost:3002');

export const SESSION_KEY = 'vlthr_session_id';
export const SESSION_DURATION = 1 * 60 * 60 * 1000; // 1 hour

In production: API_BASE is empty string, so all requests are relative. nginx proxies /api/ to backend:3001.

In development: API_BASE points to http://localhost:3002 for local backend.

Dockerfile (Multi-Stage)
# Build stage
FROM node:22-slim AS builder
WORKDIR /app
COPY package.json package-lock.json ./
RUN npm ci
COPY . .
RUN npm run build

# Serve stage
FROM nginx:alpine
COPY --from=builder /app/dist /usr/share/nginx/html
COPY nginx.conf /etc/nginx/conf.d/default.conf
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
nginx Configuration

The nginx config handles four concerns:

  • SPA fallback: All routes serve index.html (React Router handles client-side routing)
  • Asset caching: Hashed JS/CSS bundles cached for 1 year (immutable). HTML and icons are no-cache.
  • Service worker: /sw.js is never cached, ensures PWA updates are picked up immediately.
  • API proxy: /api/ requests proxy to backend:3001 with buffering disabled for SSE support. Read timeout set to 86400s (24 hours) for long-lived SSE connections.
Health Check
Docker healthcheck runs wget --spider -q http://127.0.0.1/ every 30 seconds. Verifies nginx is serving the SPA.
