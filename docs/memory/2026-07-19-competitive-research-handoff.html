The Landscape

8 labs and frameworks running algorithmic systems with Bybit. Ordered by relevance to VLTHR.

ML Astraios

What: Quantitative ML platform for crypto derivatives. Multi-timeframe transformer + LightGBM ensemble across 27 USDT perps.

Infrastructure:

  • 4-branch CNN front-end into 4-layer transformer encoder, d_model=128, seq_len=64, 105 features
  • LightGBM baseline trained on same CV splits. Predictions averaged at inference.
  • Metalabel confidence gate: binary classifier on encoder embeddings. Low-confidence calls surfaced but skipped.
  • AWS SageMaker training on ml.g5.12xlarge (4x NVIDIA A10G)
  • S3 model registry with hot-swap activation
  • FastAPI + asyncpg backend, PostgreSQL + Alembic, JWT auth
  • React 19 + Vite 6 dashboard with Lightweight Charts

Execution: Bybit Demo (default), Bybit mainnet (opt-in), Drift Protocol on Solana. Market orders with TP/SL, leverage, per-account daily loss limit.

Key advantage: Model must beat active model on dual CV-mean + PBO gate AND prove itself on Bybit demo before mainnet. Two-stage validation.

Relevance to VLTHR: Highest. Same exchange, same asset class, ML-driven, demo-first validation. Their metalabel gate is what our PipelineBrain should become.

Research yongzhe2160/trading-engine

What: Research-grade quantitative trading system for Bybit USDT perps. TSMOM strategy with statistical validation pipeline.

Infrastructure:

  • Event-driven backtester with real costs: taker 5.5 bps, maker 2.0 bps, funding on held notional at each 8h settlement
  • Equity marked-to-market every bar so drawdown reflects open-position risk
  • Newey-West (HAC) return-level significance AND fold-stability t-test, net of funding
  • Programmatic go/no-go gate before live deployment
  • Live loop with position-state persistence, exchange reconciliation, circuit breakers
  • Daily-rebalance daemon with kill-switch file and liveness heartbeat
  • FastAPI dashboard with EMA backtest, live forward tester, TSMOM signal tab

Key advantage: Statistical rigor. A strategy does not ship because it looks good on one split. It ships only if it clears HAC significance and fold-stability, net of funding.

Relevance to VLTHR: High. Their validation methodology is what our PIVP gate should become. Their funding cost tracking is what our reconciliation gap needs.

Framework Directional Scalper

What: CCXT-based multi-exchange algorithmic trading framework. 217 stars, 20 contributors, 25 releases. Most mature Bybit-focused open source project.

Infrastructure:

  • Multi-bot auto symbol rotator: runs multiple symbols concurrently
  • Strategies: linear grid, DBSCAN-based grid, hedge MFIRSI maker, trend orderbook
  • Wallet exposure limits, auto-reduce cooldown, failsafe thresholds
  • External API scraper for volume data (quantumvoid.org)
  • Docker Compose deployment

Key advantage: Battle-tested at scale. 217 stars, 20 contributors, 25 releases. Multi-symbol concurrent execution with auto-rotation.

Relevance to VLTHR: Medium. Different strategy class (grid/scalping vs trend/MR), but their multi-symbol concurrent execution pattern and auto-reduce logic are directly applicable.

ML PurpleSky

What: Hybrid ML trading system for Bybit. LightGBM + LSTM + Gating Network with meta-labeling.

Architecture:

  • LightGBM (Model B): predicts trade success from immediate features
  • LSTM (Model C): analyzes 60-bar sequences for temporal patterns
  • Gating Network (Model D): arbitrator that weights GBM vs LSTM based on market regime
  • Directional Confirmation (Model A): high-threshold trend filter
  • 50-level orderbook snapshots, taker flow, Liquidity Elasticity, Price-Liquidity Divergence, Wall Integrity

Key advantage: Mixture of Experts. The gating network dynamically weights models based on regime. More sophisticated than a static ensemble.

Framework dgbit (Cryptuon)

What: Backtest-to-live framework for Bybit. Python package + FastAPI + NNG service bus + Vue 3 dashboard.

Key design: Single-exchange scope keeps backtest and live behavior in agreement. One interface for research, simulation, and execution. NNG (nanomsg) service bus for high-frequency operations.

Agent-ready: REST API + WebSocket event stream (job.*, trade.*, signal.generated) designed for autonomous agent control. A scheduler, CI job, or agent can POST a backtest, poll for results, request a signal, place an order, and subscribe to events.

Infra Cryptex

What: Multi-tenant crypto algorithmic trading platform. Kafka pipeline (Python) + OMS/EMS microservices (C# .NET 8) + TimescaleDB.

Architecture:

Binance WS -> Exchange Connector -> Candle Aggregator -> Signal Pipeline (ML/LLM) -> Signal Router -> OMS -> EMS -> Exchange REST -> Order Fills -> OMS

Kafka topics: market-data-raw, market-data-candles, trade-signals, order-requests, validated-orders, order-fills. Each stage is a separate consumer/producer.

Key advantage: Decoupled event-driven architecture. Each pipeline stage scales independently. Pluggable signal sources (ML, LLM, or both).

Infra Muninn

What: Event-native research infrastructure for deterministic replay. Java/Spring Boot.

Core claim: Any value the system emits live can be reproduced byte-for-byte by replaying the same events later. One feature engine, not two pipelines. The engine does not know whether it is reading from a live broker or from history.

Key advantage: Solves the research/production divergence problem. Backtests pass, deployments fail, and nobody can reproduce what happened yesterday. Muninn closes that gap with one immutable event log as source of truth.

Relevance to VLTHR: High conceptually. Our backtest uses historical Parquet, our live pipeline uses REST polling. They diverge. Muninn's approach of one computation path for both is the gold standard.

Live Autarch

What: Bybit USDT Perp auto-trade workbench. Dual-plane architecture: AI-driven strategy evolution + deterministic execution.

Design: Evolution Plane generates, backtests, and swaps strategies. Execution Plane runs deterministic Python with asyncio coroutines per pair, hard-caps concurrent positions, mandatory TP/SL. Fire-and-forget orders managed by Bybit's native TP/SL.

Key advantage: Clean separation of strategy evolution from execution. The runner is purely mathematical during live trading, no LLM calls. AI handles the slower task of strategy generation.

Gap Analysis

What competitors do that VLTHR does not. Each gap has a concrete fix.

CRITICAL No Bybit Demo API integration

Who has it: Astraios, yongzhe2160, Autarch. All three use Bybit Demo API or testnet for paper trading.

What Bybit offers:

  • api-demo.bybit.com REST endpoint with isolated demo account
  • wss://stream-demo.bybit.com for private WS streams (orders, executions, positions, wallet)
  • Public market data is identical to mainnet via wss://stream.bybit.com
  • POST /v5/account/demo-apply-money to programmatically fund the demo account
  • Same V5 API surface, same order types, same position management
  • Orders persist 7 days, default rate limit (not upgradable)
VLTHR today: Simulates trades entirely inside Postgres. No exchange interaction. No slippage, no funding, no real order book. Backtest and live diverge silently.

Fix: Create a Bybit Demo account. Generate demo API keys. Route paper trades through the real Bybit V5 API instead of internal simulation. Same code path as mainnet, isolated account.

CRITICAL REST polling instead of WebSocket

Who has it: Every competitor. Astraios, Directional Scalper, PurpleSky, dgbit, Cryptex, Autarch all use WebSocket for real-time data.

MAJOR No ML model in production

Who has it: Astraios (transformer + LightGBM + metalabel), PurpleSky (LSTM + GBM + gating), MarketRegimeNet (4-model ensemble + Kelly sizing), ProfitPilot (PyTorch + XGBoost + LightGBM).

What VLTHR has: PipelineBrain class exists. BRAIN_ENABLED = False. River online classifier. Trust criteria: 30+ predictions, accuracy above random, Brier score threshold. Never reached trust threshold because it only learns from live shadow trades one at a time.

The gap: Astraios backfills historical data to train models before going live. VLTHR waits for live samples to accumulate. Astraios has 430K labeled samples. VLTHR has 25 closed trades.

Fix:

  • Backfill PipelineBrain with historical Parquet data. Generate predictions for past signals, resolve against actual outcomes. Accumulate 500+ samples in hours, not months.
  • Add a metalabel gate (like Astraios): binary classifier that predicts "will this signal be correct?" Low-confidence signals are surfaced but not traded.
  • Consider adding LightGBM as a baseline model alongside the River classifier. LightGBM is what 4 of 5 ML competitors use.
MAJOR No statistical significance testing

Who has it: yongzhe2160. Newey-West HAC significance test + fold-stability t-test, net of funding. Programmatic go/no-go gate.

What VLTHR has: 6 backtest gates (win rate, profit factor, expectancy, max drawdown, Sharpe, calibration). All threshold-based, none statistical.

Fix: Add HAC (Heteroskedasticity and Autocorrelation Consistent) significance test to the backtest gate suite. A strategy that passes all 6 threshold gates but fails HAC significance should not ship. Add bootstrap confidence intervals for win rate and expectancy.

MAJOR Monolithic orchestrator

Who has it: Cryptex (Kafka + microservices), AxiomX (Go + Kafka + K8s), crypto-oms-aws (.NET + Kafka + EKS).

What VLTHR has: Single portfolio_orchestrator.py that does data fetch, signal scan, gate evaluation, position sizing, and trade creation in one process.

Fix (phased):

  • Phase 1: Extract data ingestion, signal generation, and execution into separate Docker services communicating via Redis pub/sub (already have Redis).
  • Phase 2: Introduce Kafka or Redpanda for durable event log. Each pipeline stage becomes a consumer/producer. Enables deterministic replay (Muninn pattern).
  • Phase 3: Scale signal generation horizontally. Run multiple symbols in parallel consumers.
Not urgent. The monolith works at 5 symbols. It breaks at 50. Fix risk sizing and Demo API first. Architecture migration is Phase 3.
EDGE VLTHR advantages over competitors

12-gate pipeline: No competitor has more than 3-4 pre-trade gates. VLTHR has pre-flight, V2 filters, ranker, V7 Kelly, disabled symbols, regime, DQ, correlation, trade count, directional, risk budget, calibration. 12 gates.

DQS composite scoring: Multi-factor quality score that drives Kelly multiplier. Astraios uses a metalabel gate but not a composite quality score. PurpleSky uses a gating network but not a pre-trade quality gate.

Kelly V7 bands with MR boost: Kelly multiplier scales with DQS, with 3x boost for mean-reversion. No competitor has DQS-gated Kelly sizing.

Crowding detection: Correlation cluster detection with Kelly reduction when 2+ symbols in same cluster fire same direction. Unique to VLTHR.

Calibration gate: Calibrated probability threshold before trade approval. No competitor has calibration-aware gating.

Dynamic SL: 3-rule dynamic stop-loss system. Most competitors use static SL or ATR-based SL only.

Bottom line: VLTHR's gate system is more advanced than any competitor. The problem is not the gates. It is the execution layer underneath them.

Bybit V5 API

What Bybit offers for 1:1 simulation and real-time trading. This is the foundation for closing the execution realism gap.

Demo Trading Service

Bybit V5 API supports a demo trading account that mirrors mainnet functionality. This is not testnet. It is a separate isolated account on the mainnet infrastructure.

Endpoints:

  • REST: https://api-demo.bybit.com
  • WebSocket (private): wss://stream-demo.bybit.com
  • WebSocket (public): wss://stream.bybit.com (same as mainnet)

Setup steps:

  • Log in to mainnet Bybit account
  • Switch to Demo Trading mode
  • Generate API key and secret from the demo account
  • Use POST /v5/user/create-demo-member to programmatically create a demo sub-account
  • Use POST /v5/account/demo-apply-money to fund with virtual USDT (up to 100,000 per request)
Limitations: Orders persist 7 days only. Default rate limit, not upgradable. Not every API endpoint is available in demo mode. WS Trade is not supported on demo.

What this means for VLTHR: We can route paper trades through the real Bybit matching engine. Real slippage, real funding, real order rejection. Same code path as mainnet. One config flag to switch from demo to live.

Phase 4: Backtest with Bybit Demo API

Goal: Run a backtest that uses the same Bybit Demo API execution path as live. This is the "1:1 real-time production simulation" the user requested.

Method:

  • Run the live pipeline in demo mode for 7-30 days. Every signal that passes all 12 gates gets executed on Bybit Demo API.
  • Track: fill price vs signal price (slippage), funding paid/received, fee costs, rejection rate, actual PnL vs expected PnL.
  • Compare demo API results against internal simulation results for the same period. Measure divergence.
  • If divergence is small (under 5% on PnL), internal simulation is validated. If large, internal simulation needs correction.

Success criteria:

  • At least 20 trades executed on Demo API
  • Fill rate above 95%
  • Slippage under 10 bps average
  • Demo PnL within 10% of internal simulation PnL
  • All 12 gates functioning on real exchange data

PIVP gate: Run after 7 days of demo trading. If any Blocker or Critical issue, halt and fix before continuing.
