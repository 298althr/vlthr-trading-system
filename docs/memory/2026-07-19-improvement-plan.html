Risk Sizing

CRITICAL Every trade is 33x undersized. A notional cap overrides the risk percentage config.

Root cause: cap_position_size() in portfolio_config.py:289 caps notional to $2,000. This overrides risk_pct * kelly_mult entirely.
The bug trace

Orchestrator computes dollar risk from risk_pct * kelly_mult, derives a quantity, then caps the notional to $2,000. The cap is always binding.

# portfolio_config.py:289 def cap_position_size(position_size_1x, account_balance): return min(position_size_1x, 2000.0, # CAPITAL_PER_SYMBOL account_balance * 0.25) # SYMBOL_ALLOC_CAP

For BTC at $64,322 with 0.3% SL distance ($193):

DQSTierKellyIntendedPre-capPost-capActual
552.0%0.3x$60$19,996$2,000$6
653.0%0.7x$210$69,988$2,000$6
755.0%1.5x$750$249,956$2,000$6

Every trade across every symbol shows ~$2,000 notional. Actual risk is $6-20 per trade, which is 0.06-0.20% of the $10k account.

Dead code: per-symbol risk_pct

PER_SYMBOL_PARAMS["BTCUSDT"]["risk_pct"] = 0.05 is never read by the orchestrator. Position sizing uses RISK_TIERS (tier-based by DQS), not per-symbol risk_pct. This config value is misleading.

Fix options

Option A (minimal): Raise CAPITAL_PER_SYMBOL. But even at $10,000, a 0.3% SL gives only $30 risk. Still too small.

Option B (correct): Cap dollar risk, not notional:

def cap_dollar_risk(dollar_risk, account_balance, max_risk_pct=2.0): return min(dollar_risk, account_balance * max_risk_pct / 100)

Then size quantity from the capped dollar risk. This decouples position size from SL distance.

Option C (recommended): Remove cap_position_size from the sizing path entirely. Let risk_pct * kelly_mult determine dollar risk. Use Gate 4c (Risk Budget Ledger) and the backend per-symbol margin cap ($1,667) as the real constraints.

Bug 2a: Signal duplication (15 expired)

15 BTC trades created on Jul 17 with identical SL ($62,731.94) and TP ($63,658.19). All expired. The same signal was repeatedly submitted as PENDING without deduplication across scan iterations.

The dedup check at line 1152 only prevents duplicates within the same scan iteration, not across iterations.

Fix: Before creating a new PENDING trade, check if a PENDING trade already exists for the same symbol with the same signal_bar_utc. If so, skip.

Bug 2b: Trend_following strategy mismatch

BTC is configured as trend_following with sl_mult=2.5, tp_mult=7.5. Actual SL distances range from 0.3% to 0.8%, suggesting very tight ATR readings. BTC noise easily triggers SL before the trend develops.

4 out of 7 closed BTC trades were SL_HIT:

TradeSideSL distanceResult
#10SHORT0.80%SL_HIT -$18.99

#28SHORT0.69%SL_HIT -$17.69
#35SHORT0.44%SL_HIT -$11.30

Compare to SOL (also trend_following, 5 closed, 4 wins). SOL's lower price means ATR-based stops are proportionally wider relative to noise.

Fix options:

  • Switch BTC to mean_reversion (like ETH, BNB, XRP). BTC was range-bound $62k-65k during test period.
  • Increase sl_mult from 2.5 to 3.5-4.0 to give trends more room.
  • Add minimum SL distance floor (e.g., 0.5% for BTC).
  • Run D5 (realworld backtest) with modified params to validate.
Bug 2c: Too many non-executing signals

Even after fixing the duplication bug, BTC generates too many signals that never execute. 15 expired out of 22 total. This suggests the DQS threshold for BTC may be too low, or the V2 filters are not strict enough for BTC's current regime.

Fix plan
  • Backfill Pipeline Brain: Run predictions against historical Parquet + signal_state_log to accumulate the 30+ samples needed for trust criteria. Don't wait for live shadow trades one at a time.
  • Wire decision log into scoring: Before adaptive_scorer.py finalizes a DQS score, query signal_node_log for similar prior setups (same symbol, same strategy, similar DQS range). Let historical outcomes adjust the score by 2-5 points, not override it.
  • Add rejection analysis: Weekly job that samples rejected signals, checks what would have happened if they were approved, and reports false-positive rate per gate.
  • RCA integration: Wire pipeline Step 12 (post-flight trace) to POST failures to an RCA endpoint instead of just logging a string.

Other Gaps

Gaps 4-6: reconciliation, redundancy, and test coverage.

MAJOR No exchange reconciliation

Paper trading is simulated entirely inside the system. Nothing checks simulated fills against actual Bybit prices. The backtest assumes no slippage, no funding costs, and static crowding clusters.

Fix:

  • Record the Bybit ticker price at signal creation and at trade open/close. Compare to simulated entry/exit.
  • Track funding rate paid/received during open positions. Subtract from PnL.
  • Estimate slippage as the difference between simulated fill and next-bar open.
  • Run this for 50 trades, then feed average slippage and funding cost back into the backtest.
MAJOR No redundancy or backup
  • Single Postgres container, single pipeline container, no replicas, no failover.
  • vlthr_pgdata named volume has no backup strategy.
  • If Postgres dies mid-trade, there is no recovery story.

Fix:

  • Add pg_dump cron job to the Postgres container, writing to a mounted backup volume.
  • Add health check retry logic to the pipeline container.
  • Document recovery procedure: restore from dump, restart pipeline, verify trade state consistency.
MINOR No test suite or CI
  • test_risk_logic.py exists but is not run in any CI pipeline.
  • No automated test runs on deploy.
  • PIVP Phase 2 (Automated Debug Pass) is manual.

Fix:

  • Add pytest step to a deploy script or CI workflow.
  • Add integration test that runs one pipeline iteration against fixture data.
  • Gate deploys on test pass.
