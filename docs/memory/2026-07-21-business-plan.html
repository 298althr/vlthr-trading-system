1. Executive Summary

The original AELTHR expansion plan proposed 12 services across 4 tiers, 25 new API endpoints, 10 new database tables, and 18 new frontend pages. It was written against a TypeScript/Fastify/Neon/React Native stack that does not match the actual VLTHR codebase.

What actually exists: A Python pipeline engine with a 12-gate signal approval system, an Express.js backend with 50+ live API endpoints, a Vite/React frontend, an AI trader engine (FastAPI), dual execution on paper and Bybit demo, a VTC token economy, and 9 Docker services. The platform already generates, scores, approves, and executes trading signals with a proven backtest (480 trades, PF 2.58, expectancy $6.05).

This document reframes the expansion plan around what is built, identifies 9 business units already embedded in the code, maps 5 revenue tiers, and defines an API service contract for the separately built frontend.

Key Insight

The expansion plan underestimated the platform. VLTHR already has signal generation, dual execution, backtesting, AI analysis, market intelligence, paper trading, VTC tokenomics, and a WebSocket data service. The gap is not building from scratch. It is productizing what exists and building the missing 3 units: developer API access, webhook delivery, and historical data export.

3. Business Unit Catalog (9 Units)

Each unit is a distinct revenue-generating capability already present in the codebase. Evidence cites the actual file or endpoint.

BU-01: Signal Intelligence Service LIVE REVENUE

The core product. A 12-gate pipeline scans 6 crypto assets every 5 minutes, scores signals with DQS (Decision Quality Score), sizes positions with Kelly V7, and approves trades through calibration, regime, correlation, crowding, data quality, and risk budget gates.

Evidence: pipeline/engine/portfolio_orchestrator.py, portfolio_gates.py, v2_filters.py, signal_ranker.py, calibration_engine.py

API Endpoints:

GET  /api/signals              — list all signals
GET  /api/signals/stream       — SSE real-time signal push
POST /api/signals/:id/action   — mark executed/ignored
POST /api/signals/simulate     — generate simulated signal
GET  /api/history              — signal history
GET  /api/watchlist             — user watchlist
GET  /api/winners               — top performing signals
GET  /api/power-trades          — promoted high-conviction trades

Revenue: Free tier (3 signals/day), Pro tier (unlimited), Enterprise (API + webhook delivery)

BU-02: Dual Execution Engine LIVE REVENUE

Every approved signal trades on both paper and Bybit demo simultaneously. Same risk_pct, independent account balances. Bybit executor places real market orders with SL/TP attached at creation. Reconciliation loop checks positions each cycle, calculates PnL on close.

Evidence: pipeline/engine/bybit_executor.py (313 lines, HMAC-SHA256 auth, Bybit V5 API), shadow_runner.py, portfolio_orchestrator.py (lines 655-729 dual execution, 1717-1795 reconciliation)

API Endpoints:

GET  /api/bybit/trades         — Bybit trade list (OPEN/CLOSED/ALL)
GET  /api/bybit/account        — Bybit + paper account summary with stats
GET  /api/bybit/positions      — live Bybit positions with unrealized PnL
GET  /api/bybit/orders         — live Bybit open orders
GET  /api/bybit/closed-pnl     — Bybit closed PnL history from exchange
GET  /api/bybit/compare        — side-by-side paper vs Bybit performance

Revenue: Pro tier (paper only), Enterprise (Bybit live execution, managed accounts)

Full paper trading simulation with account management, position sizing, leverage, entry/exit tracking, and PnL calculation. Users can manually open/close trades or auto-follow signals.

VTC Token Integration

VTC tokens cross-cut all tiers. Users earn VTC by maintaining high signal accuracy (Pro+ and above). VTC can be burned to unlock time-limited Enterprise features, reducing the cash barrier to entry. This creates a performance-meritocratic upgrade path: good traders get premium tools without paying cash.
