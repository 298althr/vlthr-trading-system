Root cause: get_sl_tp() accepted a symbol parameter but never used it. All signals got generic tier multipliers (fair: sl=3.0, tp=5.0) instead of per-symbol values (BTCUSDT: sl=2.5, tp=7.5).

  • backtest_runner.py: Both call sites pass symbol= param

Leverage Reconciliation
COMPLETE

Problem: Bybit account leverage was 10x. All position sizing math uses MAX_LEVERAGE = 4. A 10x account with 4x sizing means margin calls happen at the wrong threshold.

Fix: Added set_leverage(symbol, leverage, marginMode) to bybit_executor.py. Called once at process startup for each active symbol. Logs the reconciliation result.

  • Method calls Bybit V5 /v5/position/set-leverage
  • Runs once per container lifetime (not per scan cycle)
  • Fails gracefully if API is unavailable (logs warning, continues)

A3
Daily Loss Circuit Breaker
COMPLETE

Problem: No mechanism to stop trading after consecutive losses. A bad day could compound into a 10%+ drawdown before the existing 20% account-level halt triggers.

Fix: Added _check_daily_loss_breaker() to orchestrator. Queries closed trades since UTC midnight, sums net PnL, and halts new approvals if loss exceeds daily_loss_halt_pct (2%) of account balance.

  • Resets at UTC midnight (natural day boundary)
  • Only blocks new approvals. Open trades continue to manage normally.
  • Logs the breach with exact PnL and threshold values
  • Config: PORTFOLIO["daily_loss_halt_pct"] = 2.0
2 unit tests pass Config validated
B1
Regime Router Gate
COMPLETE

New module: pipeline/engine/regime_router.py

Rule-based regime classifier using three signals:

  • ADX: Directional movement strength (trend >= 25, range < 20)
  • Kaufman Efficiency Ratio: |net displacement| / sum(|bar-to-bar changes|) over 20 bars. ER near 1 = trending, near 0 = ranging.
  • ATR Percentile Rank: 50-bar rank of ATR/close. >= 0.80 = volatile.

Gate logic:

  • TRENDING: allow trend_following, veto mean_reversion
  • RANGING: allow mean_reversion, veto trend_following
  • VOLATILE: veto both unless DQS >= 60
  • MIXED: allow both (safe default, let downstream gates decide)

Wired as Gate 0d, between existing Gate 0c (regime DQS) and Gate 1 (data quality). Uses the same enriched DataFrame cache.

10 unit tests pass No new strategy added
B2
Shadow Validation Runner
COMPLETE

New module: pipeline/engine/shadow_runner.py

Addresses the audit's "self-certified gates" problem. The pipeline's gates run inside the same process that benefits from approving trades. Shadow runner re-checks independently:

  • Kelly veto recheck: Re-computes Kelly from DQS + strategy, verifies it wasn't bypassed
  • Daily breaker recheck: Confirms breaker wasn't tripped at approval time
  • Correlation recheck: Verifies symbol wasn't already open
  • Risk budget recheck: Confirms total open risk was within portfolio limit
  • Bybit vs paper reconciliation: Compares open positions on both ledgers, flags mismatches

Writes results to validation_log table. Does not modify any trade state. Pure observer.

Wired as Step 5d (after paper trade creation, before portfolio snapshot). Bybit reconciliation runs in Step 6b alongside existing reconciliation.
