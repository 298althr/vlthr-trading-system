2. Bybit Demo: Root Cause & Fix

Problem

Frontend showed Bybit balance as $0.00 with connected: true. No Bybit trades visible. The GET /api/bybit/account endpoint returned zero balance despite valid API keys.

Root Cause

DNS resolution failure inside Docker containers.

The host uses systemd-resolved listening on 127.0.0.53. Docker copied this into container /etc/resolv.conf, but 127.0.0.53 is unreachable from inside containers. The Bybit client (bybit-client.cjs) got EAI_AGAIN / ECONNREFUSED when resolving api-demo.bybit.com. getWalletBalance() returned null, and the endpoint defaulted to 0.00.

Fix Applied

Added explicit DNS servers to 3 services in docker-compose.yml:

Current Ingestion Status

Ingestion is currently working — all recent fetches show status=ok, gaps_found=0. The staleness errors were from the Docker restart window (~50 min downtime). The pipeline's freshness threshold (45 min for 15m bars) was exceeded during the outage, and the pipeline hasn't recovered because:

  1. Pre-flight rejects stale data before it reaches the scan
  2. Signals that were generated before the outage expired during the downtime
  3. New signals need fresh 15m bar data, which takes 1-2 cycles to accumulate post-restart
