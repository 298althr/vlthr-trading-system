How the Two Plans Connect

The two plans are not independent. They share three connection points:

  1. Regime classification input. The session+regime plan (Phase 2) trains an HMM on log returns + realized vol. The pattern/feature spec generates pat_bos_detected, pat_choch_detected, pat_wyckoff_phase, and pat_trend_structure (HH/HL vs LH/LL). These are regime-transition candidate features. Once pattern Phases 1-3 are complete, feed these columns into the HMM training set as additional observation dimensions. This is the bridge between the two workstreams.
  2. Strategy resolution. The session+regime plan creates get_strategy(symbol, session, regime). The pattern/feature spec's confluence_score and pat_wyckoff_phase fields provide additional context that could inform strategy selection in a future iteration. For now, pattern/feature fields are logged but not used in strategy resolution until Phase 5.
  3. DQS scoring. Both plans eventually modify adaptive_scorer.py. Session+regime work changes how get_symbol_params is called (passing session). Pattern/feature Phase 5 adds a pattern_raw domain to the DQS weighted-max. These changes must be merged carefully. Do session+regime Phase 1-2 first, then pattern/feature Phase 5, so the DQS modification happens on top of a session-aware base.

7. The Plan to Execute

The full plan is at docs/architecture/session-regime-aware-parameterization-plan.html. Read it in full before starting. Summary of phases:

Phase 0: Statistical Gate Infrastructure (build first)

  • Create backtest/stat_gates.py with Mann-Whitney U, sample-size validator, DSR calculator, WFE calculator
  • Unit tests with synthetic data
  • Gate: all 4 functions pass unit tests

Phase 1: Session-Aware Parameters

  • Standardize session definitions to 4 sessions across all modules
  • Run Mann-Whitney U test per symbol across sessions using existing backtest results
  • Build SESSION_PARAMS[symbol][session] config with fallback chain
  • Calibrate via rolling WFO (3:1 IS:OOS, Calmar fitness, 3 free params max)
  • Wire get_symbol_params(symbol, session) into orchestrator, scorer, backtest
  • Gate: WFE >= 0.5, OOS PF/WR beats baseline, Mann-Whitney p < 0.05 for 50%+ of splits

Phase 2: Regime-Specific Strategy Selection

  • Train Gaussian HMM per symbol (hmmlearn, 2-3 states, log returns + realized vol)
  • get_strategy(symbol, session, regime) function with regime override
  • Hierarchical shrinkage: sparse cells blend toward session-only parent
  • Update v2_filters and adaptive_scorer to use resolved strategy
  • Gate: 30 trades per param floor + Mann-Whitney p < 0.05 vs parent session bucket

Phase 3: Backtest Calibration and Overfitting Audit

  • Three-config comparison: baseline vs session-aware vs session+regime-aware
  • Rolling WFO then CPCV as final arbiter
  • DSR computation correcting for total trials across Phase 1+2
  • Gate: DSR >= 0.80, CPCV PBO < 0.50

Phase 4: Shadow Deployment and Live Rollout

  • Resolve params via session + regime at signal time
  • Store resolved_session, resolved_regime, resolved_strategy on every trade
  • 2-4 weeks shadow per cell, monitor live vs OOS expectation
  • Gate: live WR and PF within 20% of OOS expectation per cell
