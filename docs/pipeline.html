Overview

The pipeline engine is the core decision-making service. It runs a 5-minute loop that scans 5 symbols, scores signals with the adaptive DQS scorer, tracks signal state and trajectory, ranks and filters through 12 portfolio gates, and upserts approved signals to PostgreSQL. An embedded FastAPI health server on port 8200 exposes run status.

Iteration Flow

Each 5-minute iteration runs through these steps in sequence. The entire flow is orchestrated by portfolio_orchestrator.py:run_iteration().

1
Pre-Flight Checks
safety_layer.py verifies data freshness, checks circuit breaker (3 critical errors in 1h = halt), validates account balance. Returns False to abort if any check fails.
2
Scan All Symbols
Load enriched Parquet data for each symbol. Apply V2 filters (daily bias, RSI momentum, BTC correlation). Generate raw signal candidates with entry/SL/TP from per-symbol params.
3
Score with DQS
adaptive_scorer.py computes Data Quality Score (0-100). Weighted average of technical (40%), structure (30%), context (30%) domains. Modifiers: ADX trend multiplier, RSI pullback bonus, liquidity bonus, session/symbol multipliers, contradiction penalty.
4
ML Prediction (Shadow)
pipeline_brain.py runs River online classifier to predict favorable next-15m move. Shadow mode only until trust criteria met (30+ samples, 55% accuracy, Brier < 0.24, positive shadow PnL for 5 consecutive days).
5
State and Trajectory
signal_state_manager.py updates signal_state (1 row per symbol) and appends to signal_state_log. Tracks DQS trajectory: 3 consecutive improvements = +5 bonus, 2 consecutive declines = -10 penalty and expire. Signals expire after 2 hours.
6
Rank and Filter
signal_ranker.py filters to adjusted_score >= 50, sorts by score then symbol Sharpe, deduplicates to 1 signal per symbol.
7
Crowding Detection (Treatment B)
Detect when 2+ symbols in same correlation cluster fire same direction with DQS within 5 points. Reduces Kelly by 50% for crowded signals.
8
12-Gate Sequence
Each signal passes through 12 portfolio gates. See the Gates tab for full details. Any gate failure stops the signal.
9
Upsert to Database
Approved signals upserted to high_confidence_signals table. Risk ledger updated. Trade count log updated.
10
Portfolio Snapshot
Write point-in-time snapshot to portfolio_snapshot: balance, equity, margin, total open risk, active trades count, daily trades count, highest/lowest active DQS.
11
Telegram Alert
If EXCELLENT signal passes all gates, send Telegram alert to trading channel. Also alerts on trade closures.
12
Post-Flight and Trace
safety_layer.py runs post-flight invariants (risk bounds, drawdown, signal count spike). pipeline_trace.py writes per-node trace rows. pipeline_heartbeat.py writes heartbeat row. Health server updates in-memory state.

12-Gate Sequence

Every signal must pass all 12 gates in order. One failure stops the signal. Gates are implemented in portfolio_orchestrator.py and portfolio_gates.py.

V2 Filters (Gate 2 Detail)

Applied after DQS scoring but before trade entry. Implemented in v2_filters.py.

  • Daily bias: EMA50 + RSI on daily bars. Rejects counter-trend signals.
  • RSI momentum: For trend_following only. Rejects SHORT when RSI rising, LONG when RSI falling. Mean_reversion bypasses this (rising RSI into overbought IS the short signal).
  • Volume confirmation: Requires volume above recent average.
  • BTC correlation: XRP signals filtered against BTC momentum.
  • TP scaling: Take-profit scaled by ATR percentile.
Calibration Gate
Threshold softened from 0.48 to 0.40 because only 35 calibration samples exist. The 0.48 threshold was too restrictive with unreliable estimates. Will tighten as more trade history accumulates.

Health Server

An embedded FastAPI server runs in a background thread on port 8200. It provides health status for Docker and the dashboard.

State Management

Health state is stored in a thread-safe dict protected by a Lock. The main pipeline loop calls update_last_run() after each iteration. The FastAPI server reads from this dict on each request.

_last_run = {
    "status": "unknown",
    "run_time": None,
    "signals_scanned": 0,
    "signals_approved": 0,
    "duration_ms": 0,
    "abort_reason": None,
    "loop_interval_sec": 300,
}
Docker Health Check
Docker healthcheck runs python -c "urllib.request.urlopen('http://localhost:8200/health')" every 30 seconds. Start period: 60 seconds. Retries: 3.

Notable Choices
  • Prefect disabled: DISABLE_PREFECT=true. The Prefect flow wrapper is available but disabled to reduce complexity. The pipeline runs as a plain Python loop.
  • Data read-only: The pipeline never writes to Parquet. It only reads enriched data produced by the data-ingestion service.
  • Engine code read-only: Source mounted read-only. Changes require container restart.
  • Logs writable: Log directory is writable for runtime log output.
