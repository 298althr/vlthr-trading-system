Critical Finding

The system has zero pattern recognition. It evaluates the current bar's indicator values without analyzing price geometry, multi-bar structures, or chart formations. This means the system cannot distinguish a breakout from a false push, a pullback from a reversal, or accumulation from distribution. All trading decisions rely on scalar indicator values at a single point in time.

Existing Infrastructure

The enriched DataFrame already contains OHLCV, open_interest, funding_rate, buy/sell ratios, ATR, RSI, ADX, session, and 4h context. All pattern detection and feature engineering can operate on this existing DataFrame. No new data sources, services, or infrastructure required. Pure Python functions using pandas, numpy, and scipy.

2.1 Trend Line Patterns (5)

2.1.1 Converging Trend Lines (Wedge)
Rising Wedge Falling Wedge Symmetrical Triangle

Inputs: Last 40-60 bars of OHLCV. Pivot highs and pivot lows.

Algorithm:

  • Detect pivot highs and lows using fractal method (left=3, right=3)
  • Linear regression on pivot highs: slope_max, intercept_max, r_max
  • Linear regression on pivot lows: slope_min, intercept_min, r_min
  • Convergence test: intersection point exists ahead, within 3x lookback distance
  • Slope ratio test: 0.75 and 1.25 (same direction, converging)

Formula:

# Pivot detection
pivot_high[i] = high[i] == max(high[i-3 : i+4])
pivot_low[i]  = low[i]  == min(low[i-3  : i+4])

# Linear regression on pivots
slope_max, interc_max, r_max = scipy.stats.linregress(x_max, y_max)
slope_min, interc_min, r_min = scipy.stats.linregress(x_min, y_min)

# Convergence: intersection ahead
x_intersect = (interc_min - interc_max) / (slope_max - slope_min)
converges = x_intersect > max(all_pivot_xs)
           and x_intersect - max(all_pivot_xs) < 3 * lookback

# Classification
if slope_min > 0 and slope_max > 0 and slope_min/slope_max in [0.75, 1.25]:
    pattern = "rising_wedge"  # bearish
elif slope_min < 0 and slope_max < 0 and slope_min/slope_max in [0.75, 1.25]:
    pattern = "falling_wedge"  # bullish
elif slope_max < 0 and slope_min > 0:
    pattern = "symmetrical_triangle"  # neutral, breakout-dependent

Output fields: wedge_detected, wedge_type, wedge_strength (min(r_max, r_min)), wedge_bars_to_apex, wedge_slope_ratio

Reference: zeta-zetra/code wedge.py on GitHub. Uses scipy.stats.linregress with r-value threshold of 0.9.

2.2 Support / Resistance (4)

2.2.1 Horizontal Support / Resistance Multi-touch

Algorithm: Cluster price levels where price reversed 3+ times.

# Identify all pivot highs and lows
pivots = list(pivot_highs) + list(pivot_lows)

# Cluster by price proximity (within 0.5 ATR)
clusters = []
for p in pivots:
    placed = False
    for c in clusters:
        if abs(p - c.center) < 0.5 * atr:
            c.add(p)
            placed = True
            break
    if not placed:
        clusters.append(Cluster(center=p, touches=[p]))

# Significant levels: 3+ touches
sr_levels = [c for c in clusters if len(c.touches) >= 3]
near_support = any(abs(close - s.center) < 0.5 * atr for s in sr_levels if s.center < close)
near_resistance = any(abs(close - r.center) < 0.5 * atr for r in sr_levels if r.center > close)

Output: sr_level_count, near_support, near_resistance, nearest_support_dist_atr, nearest_resistance_dist_atr, support_touches, resistance_touches

Reference: keithorange/PatternPy implements horizontal S/R with similar clustering approach.

2.2.3 Dynamic Resistance (Falling) Bearish

2.2.4 Break of Structure (BoS) / Change of Character (CHoCH) Smart Money Concept

Algorithm: Detect swing highs/lows, then classify break as continuation (BoS) or reversal (CHoCH).

# Track swing sequence
swings = detect_swings(df, left=3, right=3)

# Last confirmed swing high/low
last_swing_high = swings[-2].price if swings[-2].type == "high"
last_swing_low  = swings[-2].price if swings[-2].type == "low"

# Bullish BoS: close breaks above last swing high in uptrend
bullish_bos = close > last_swing_high and trend == "up"

# Bearish CHoCH: close breaks below last swing low in uptrend (reversal)
bearish_choch = close < last_swing_low and trend == "up"

# Bullish CHoCH: close breaks above last swing high in downtrend (reversal)
bullish_choch = close > last_swing_high and trend == "down"

Output: bos_detected, bos_type (continuation/reversal), bos_direction, choch_detected, choch_direction

Reference: fortunato/pymarket-structure implements BoS/CHoCH with 67 output columns.

2.3.1 Price Curvature (Quadratic Fit) Mathematical

Algorithm: Fit quadratic polynomial to last N closes. Extract curvature coefficient.

# Quadratic fit: y = a*x^2 + b*x + c
x = np.arange(len(closes[-60:]))
coeffs = np.polyfit(x, closes[-60:], deg=2)
curvature = coeffs[0]  # second derivative / 2

# Normalize to ATR units
curvature_atr = curvature / atr

# Classification
if curvature_atr > threshold_bullish:
    curve_type = "convex_up"    # accumulation bottom
elif curvature_atr < -threshold_bearish:
    curve_type = "concave_down"  # distribution top
else:
    curve_type = "linear"

Output: price_curvature, price_curvature_atr, curve_type, curve_r_squared

2.4 Accumulation / Distribution (3)

2.4.1 Wyckoff Phase Detection Multi-stage

Algorithm: Detect trading range, then classify phase A-E using volume, price, and structure signals.

# Step 1: Detect trading range
support, resistance = detect_range(pivots, atr)
range_size = resistance - support
in_range = range_size < 5 * atr and touches >= 4

# Step 2: Phase scoring
scores = {"phase_a": 0, "phase_b": 0, "phase_c": 0, "phase_d": 0, "phase_e": 0}

# Phase A: Selling/buying climax + automatic reaction
if detect_selling_climax(volume, price): scores["phase_a"] += 2.0
if detect_automatic_reaction(price): scores["phase_a"] += 1.5

# Phase B: Secondary tests, OBV rising while price flat
if count_secondary_tests(support) > 0: scores["phase_b"] += 1.5 * count
if obv_rising_and_price_flat(): scores["phase_b"] += 1.0

# Phase C: Spring (price dips below support then recovers)
if detect_spring(close, support): scores["phase_c"] += 3.0
if detect_upthrust(close, resistance): scores["phase_c"] += 3.0

# Phase D: Sign of Strength (SOS) or Sign of Weakness (SOW)
if detect_sos(close, resistance): scores["phase_d"] += 2.0
if detect_sow(close, support): scores["phase_d"] += 2.0

# Phase E: Breakout confirmed
if price_above_resistance and trend_bullish: scores["phase_e"] += 1.5

wyckoff_phase = argmax(scores)
wyckoff_confidence = max(scores.values()) / sum(scores.values())

Output: wyckoff_phase (A-E), wyckoff_sub_phase, wyckoff_confidence, wyckoff_range_support, wyckoff_range_resistance

Reference: gopheroid/go-wyckoff spec, Martinolli/marketflow WyckoffAnalyzer, srlcarlg/srl-python-indicators WeisWyckoffSystem.

2.4.2 Volume Spread Analysis (VSA) Effort vs Result

Algorithm: Compare bar spread (high-low) to volume. Detect effort without result.

# Effort = volume, Result = price spread
spread = (high - low) / close
vol_effort = volume / volume_mean_20

# Anomalies
narrow_spread_high_vol = spread < 0.3 * avg_spread and vol_effort > 2.0  # effort, no result
wide_spread_low_vol = spread > 2.0 * avg_spread and vol_effort < 0.5    # result, no effort

# Upthrust: wide spread up, close near low, high volume
upthrust = (close - low) < 0.3 * (high - low) and vol_effort > 1.5 and spread > avg_spread

# Spring: wide spread down, close near high, high volume
spring = (high - close) < 0.3 * (high - low) and vol_effort > 1.5 and spread > avg_spread

Output: vsa_narrow_high_vol, vsa_wide_low_vol, vsa_upthrust, vsa_spring, vsa_effort_result_ratio

2.4.3 Order Block Detection Institutional

Algorithm: Identify last down-candle before a strong bullish move (bullish OB) or last up-candle before strong bearish move (bearish OB).

# Bullish order block: last bearish candle before strong bullish move
for i in range(len(df)-2, max(0, len(df)-20), -1):
    if df.close[i] < df.open[i]:  # bearish candle
        next_move = (df.close[i+2] - df.close[i]) / df.close[i]
        if next_move > 2 * atr_pct:  # strong bullish move follows
            ob_high = df.high[i]
            ob_low = df.low[i]
            price_in_ob = ob_low <= close <= ob_high
            break

3 Feature Engineering Catalog

25 engineered features across 5 categories. Each feature is derived from existing raw or computed features. These are not patterns. They are higher-order numerical transformations that capture relationships, normalizations, and conditional states that the raw indicators alone do not express.

3.1 Ratio Features (6)

Ratio features express the relationship between two existing features as a single scalar. They normalize across symbols and price levels.

FeatureFormulaRationale
oi_to_volume_ratio open_interest / rolling_mean(volume, 20) High OI relative to volume signals positioning buildup without churn. Potential squeeze setup.
funding_to_atr_ratio funding_rate / (atr / close) Normalizes funding cost against volatility. High funding in low vol = crowded trade.
ls_ratio_spread buyRatio - sellRatio Net sentiment from long/short ratio. Positive = bullish crowd, negative = bearish crowd.
volume_turnover_ratio volume * close / turnover Detects average trade size. Low ratio = large traders dominant. High ratio = retail dominant.
rsi_to_adx_ratio rsi / (adx + 1) Momentum relative to trend strength. High RSI with low ADX = fading momentum. Low RSI with high ADX = strong counter-trend.
price_to_vwap_dev (close - vwap_20) / atr Distance from volume-weighted average price in ATR units. Mean reversion signal.

3.2 Composite Features (5)

Composite features combine 3+ raw features into a single score that captures a multi-dimensional market state.

FeatureFormulaRationale
momentum_composite (rsi - 50) / 50 * adx / 50 * sign(ctx_log_ret_4h) Unified momentum score. Combines RSI direction, ADX strength, and 4h context. Range: -1 to +1.
positioning_composite sigmoid(ls_ratio_spread * 2) * sigmoid(funding_z * 2) * sign(oi_delta_24) Combines L/S ratio, funding z-score, and OI change direction. Detects crowded positioning.
volatility_regime_score atr_rank * 0.5 + vol_pctile_96 * 0.3 + (1 - efficiency_ratio) * 0.2 Composite volatility estimate. High = volatile/choppy. Low = calm/trending.
structure_quality_score adx / 50 * 0.4 + efficiency_ratio * 0.3 + (1 - atr_rank) * 0.3 Measures how clean the trend is. High = strong directional move. Low = noisy/choppy.
confluence_score sum([near_support, rising_support, bullish_bos, wedge_bullish, cdl_hammer]) / 5 Count of bullish pattern features active simultaneously. Range: 0 to 1. High confluence = high probability setup.

3.3 Z-Score Features (6)

Z-score features normalize any feature against its rolling statistics. This makes cross-symbol and cross-time comparison valid. All z-scores use a 96-bar (24h) lookback window.

FeatureFormulaRationale
rsi_zscore_96 (rsi - rolling_mean(rsi, 96)) / rolling_std(rsi, 96) RSI relative to its recent range. Z > 2 = overbought by historical standard. Z < -2 = oversold.
volume_zscore_96 (volume - rolling_mean(volume, 96)) / rolling_std(volume, 96) Volume spike detection. Z > 2 = abnormal volume. Used for breakout confirmation.
funding_zscore_96 (funding_rate - rolling_mean(funding_rate, 96)) / rolling_std(funding_rate, 96) Funding rate anomaly. Extreme positive = crowded long. Extreme negative = crowded short.
oi_zscore_96 (open_interest - rolling_mean(open_interest, 96)) / rolling_std(open_interest, 96) OI anomaly. Sudden OI spike with price move = new positions entering. Sudden drop = unwind.
spread_zscore_96 ((high - low) - rolling_mean(high - low, 96)) / rolling_std(high - low, 96) Bar spread anomaly. Detects volatility expansion or contraction relative to recent history.
buy_ratio_zscore_96 (buyRatio - rolling_mean(buyRatio, 96)) / rolling_std(buyRatio, 96) Sentiment shift detection. Sudden z-score change = potential directional move building.

3.4 Conditional Features (4)

Conditional features are binary or categorical states derived from threshold logic on existing features. They encode market context that gates or modifies trading behavior.

FeatureFormulaRationale

liquidity_dry_up 1 if volume_zscore_96 < -1.5 and oi_zscore_96 < -1.0 else 0 Both volume and OI dropping. Market participants exiting. High risk of choppy, low-liquidity conditions.

DQS Integration Plan

The DQS formula gains a new domain: pattern_raw. Weight allocation shifts to accommodate it.

# Current
DQS = tech_raw * 0.40 + struct_raw * 0.30 + ctx_raw * 0.30 + bonuses - penalties

# Proposed (Phase 5)
DQS = tech_raw * 0.30 + struct_raw * 0.25 + ctx_raw * 0.20 + pattern_raw * 0.25
      + bonuses - penalties

pattern_raw is computed from the 100 pattern output fields:

pattern_raw = (
    confluence_score * 30        # 0-1, weighted highest
    + wyckoff_confidence * 20    # 0-1, phase C/D/E bullish bias
    + wedge_strength * 10        # 0-1, pattern quality
    + bos_detected * 10          # 0/1, structure break
    + sr_proximity_score * 10    # 0-1, near support/resistance
    + cdl_pattern_count * 5      # 0-8, candlestick confluence
    + trend_break_retest * 5     # 0/1, confirmed breakout
    + curvature_alignment * 10   # -1 to +1, price/vol curvature agreement
) * pattern_regime_mult

pattern_regime_mult adjusts pattern weight by regime:

  • TRENDING: 1.2 (patterns more reliable in trends)
  • RANGING: 0.8 (patterns less reliable in chop)
  • VOLATILE: 0.6 (patterns unreliable in high vol)
  • MIXED: 1.0 (neutral)

V2 Filter Additions

  • Pattern confirmation filter: require confluence_score >= 0.3 for DQS 40-60 signals
  • Wyckoff phase filter: reject LONG if wyckoff_phase == "distribution", reject SHORT if wyckoff_phase == "accumulation"
  • Liquidity sweep filter: if liquidity_sweep detected, require higher DQS (+10)

Validation Approach: A/B Comparison Phases 1-4

Phases 1-4 do not modify DQS. Validation is observational. Run the backtest with pattern and feature columns logged but not used in scoring. Compare trade outcomes to the frozen baseline. Trades should be identical. Any difference indicates a bug (data leakage, column collision, or accidental DQS modification).

assert backtest_wr == baseline_wr

# Only new columns should be added
new_cols = set(backtest_cols) - set(baseline_cols)
assert all(col.startswith("pat_") or col.startswith("feat_") for col in new_cols)
Validation Approach: A/B Test with DQS Changes Phase 5-6

Phase 5 modifies DQS. Run two backtests: baseline (original DQS) and treatment (modified DQS with pattern_raw). Compare all metrics. Treatment must pass all 6 gates and not degrade any metric beyond defined thresholds. 

# Phase 5-6 validation: treatment vs baseline
treatment = run_backtest(dqs="modified", patterns=True, features=True)
baseline  = run_backtest(dqs="original",  patterns=True, features=True)  # log only

# Gate checks (see 5.2)
for gate in GATES:
    assert gate.check(treatment, baseline), f"Gate {gate.name} FAILED"

IC Analysis Protocol

For each phase (1-4), compute Information Coefficient (IC) for every new field: Spearman rank correlation between the field value and 12-bar forward returns. IC is computed per symbol, then averaged. Fields with |IC| < 0.02 across all symbols are flagged as low-signal and excluded from DQS integration in Phase 5. Fields with |IC| ≥ 0.05 are high-priority candidates for DQS integration.

Look-Ahead Bias Prevention

All pattern functions receive only the enriched slice up to and including the current bar. Pivot detection uses right=3, meaning a pivot is confirmed 3 bars after it forms. This is by design. The 3-bar delay is the cost of confirming a pivot. No pattern function may access data beyond the current bar index. Unit tests must verify this by shifting the DataFrame and confirming output stability for the confirmed portion.

Integration Strategy

Why Not Install These Libraries?
Decision: No New Dependencies

We do not install TA-Lib, pandas-ta, finta, or any pattern library as a dependency. Reasons:

  • TA-Lib requires C compilation. Adds build complexity to Docker.
  • pandas-ta is abandoned (last update 2023). Import conflicts with existing code.
  • Pattern libraries have varying APIs, data formats, and assumptions. Integrating multiple libraries creates maintenance burden.
  • Our needs are specific. 30 patterns and 25 features. Not 163 indicators. Reimplementing is faster than adapting a general library.
  • Pure Python functions on the existing DataFrame avoid serialization, format conversion, and dependency management overhead.

7 Risk Assessment & Do-Not-Touch List

Risk Assessment

Implementation Risks 8 risks identified
IDRiskSeverityMitigation
R1 Look-ahead bias in pattern detection. Pivot detection with right=3 uses 3 future bars. If pattern function accesses bars beyond the current index, signals will have unrealistically high win rates in backtest but fail live. Critical Unit tests: feed shifted DataFrame, verify output for confirmed bars does not change. All pattern functions receive df.iloc[:idx+1] only.
R2 DQS weight rebalancing degrades performance. Shifting weights from tech/struct/ctx to pattern_raw may reduce the influence of proven indicators. Critical Phase 5 A/B test against frozen baseline. 6 gates must pass. If PF drops below 2.50, revert. Iterative weight tuning with max 3 attempts.
R3 Pattern overfitting. 125 new features on 925 trades risks curve fitting. Patterns may learn noise specific to the 180-day window. High IC analysis to filter features. Only features with |IC| ≥ 0.02 enter DQS. Walk-forward validation: split 180 days into 120 train / 60 test. Verify patterns stable across both halves.
R4 Computation latency. 30 pattern functions + 25 feature functions per symbol per scan may exceed 5-minute scan budget. High Benchmark: target < 50ms per symbol. Profile each function. Vectorize with numpy where possible. Cache pivot detection (shared across patterns).
R5 NaN propagation. Z-score features need 96-bar warmup. Curvature needs 60 bars. Early bars in the dataset will have NaN pattern fields. Medium All pattern/feature functions must return 0.0 or neutral value for insufficient data. Never NaN. Post-computation NaN check in backtest runner.
R6 Pattern correlation / redundancy. Multiple patterns may detect the same market condition (e.g., rising support + ascending channel + HH/HL). This inflates confluence_score without adding information. Medium Pattern co-occurrence matrix in diagnostic metrics. If two patterns co-occur > 80%, merge or drop one. Confluence score weights adjusted by IC, not raw count.
R7 Symbol-specific pattern failure. Patterns calibrated on BTC may not work on SOL (different volatility, liquidity, trend behavior). Medium Gate 5: per-symbol consistency check. If a pattern degrades a specific symbol, disable it for that symbol via config. Symbol-specific pattern weights in Phase 6.
R8 Wyckoff phase misclassification. Wyckoff is subjective. Algorithmic phase detection may produce false positives, especially in crypto which rarely forms clean ranges. Low Wyckoff confidence threshold. Only phases with confidence > 0.5 influence DQS. Phase C (spring/upthrust) gets 3x weight in scoring. Phase B gets 0.5x (too noisy).
