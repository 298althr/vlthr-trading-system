Overview

The PostgreSQL service runs TimescaleDB on PostgreSQL 15. It stores all relational state for the VLTHR pipeline: signal tracking, risk ledger, portfolio snapshots, trade counts, predictions, model state, pipeline traces, and error logs.

Docker Service

Migration Script

The migration script postgres/db_migration.py runs automatically on first container startup via Docker's docker-entrypoint-initdb.d mechanism. It creates all tables, indexes, and constraints if they do not exist.

Migration Flow
  1. Load .env to get DB_URL
  2. Connect to PostgreSQL (tries port 5432, falls back to 6543)
  3. Execute NEW_TABLES_SQL — creates all 10 tables with IF NOT EXISTS
  4. Update signal_state unique constraint from (symbol) to (symbol, signal_bar_utc)
  5. Add columns: side, strategy, session to signal_state
  6. Create all performance indexes
Idempotency

All DDL uses CREATE TABLE IF NOT EXISTS and ADD COLUMN IF NOT EXISTS. The migration is safe to run multiple times. Existing data is never modified or deleted.

Manual Migration
To run the migration manually: python postgres/db_migration.py. Requires DB_URL in environment or .env file.

Docker Configuration

Service Definition
postgres:
  image: timescale/timescaledb:latest-pg15
  container_name: vlthr-postgres
  environment:
    - POSTGRES_PASSWORD=${POSTGRES_PASSWORD:-your_postgres_password}
    - POSTGRES_DB=${POSTGRES_DB:-postgres}
  volumes:
    - vlthr_pgdata:/var/lib/postgresql/data
    - ./postgres/db_migration.py:/docker-entrypoint-initdb.d/db_migration.py:ro
  networks:
    - vlthr-net
  restart: unless-stopped
  healthcheck:
    test: ["CMD", "pg_isready", "-U", "postgres"]
    interval: 10s
    timeout: 5s
    retries: 5
    start_period: 30s
Volume

Data is persisted in the named Docker volume vlthr_pgdata. This survives container rebuilds and restarts. The migration script is mounted read-only into docker-entrypoint-initdb.d and executes only on first database initialization.

Health Check
Docker healthcheck runs pg_isready -U postgres every 10 seconds. Other services (data-ingestion, pipeline, ai-trader-engine, telegram) depend on this health check passing before starting.

Connection Configuration

Connection String

All services connect using the DB_URL environment variable, set in docker-compose.yml:

DB_URL=postgresql://postgres:${POSTGRES_PASSWORD:-your_postgres_password}@vlthr-postgres:5432/postgres
Password

The password is read from .env as POSTGRES_PASSWORD. If not set, defaults to your_postgres_password for local development. Production deployments must set a strong password in .env.

Network

All services connect via the vlthr-dashboard-net Docker bridge network. The PostgreSQL container is reachable at vlthr-postgres:5432 from other containers. No external port is exposed.

Fallback Port
The migration script tries port 5432 first, then falls back to port 6543. This handles environments where PostgreSQL runs on a non-standard port.
