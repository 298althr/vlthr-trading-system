Overview

Redis 7 (Alpine) serves as the in-memory cache layer for the VLTHR stack. The backend Express API uses it to cache API responses and reduce PostgreSQL load. The pipeline service uses it for ephemeral state coordination.

Design Decisions
DecisionValueRationale
Max memory256 MBCache-only workload. Sufficient for API response caching without competing with PostgreSQL buffer pool.
Eviction policyallkeys-lruEvict least recently used keys when memory is full. No key is permanent. All data is re-derivable from PostgreSQL or Parquet.
PersistenceNone (save "")Cache data is ephemeral. No RDB snapshots, no AOF. Container restart clears all keys. No data loss risk because nothing in Redis is authoritative.
Append-only fileDisabledNo durability needed for cache. Avoids disk I/O overhead.
Docker Service
Runs as vlthr-dashboard-redis container. Image: redis:7-alpine. Configuration loaded from redis/redis.conf. No health check defined (Redis is inherently reliable). Restart policy: unless-stopped.

Configuration

The Redis configuration file is mounted read-only from redis/redis.conf.

redis.conf
# VLTHR Redis Configuration
# Used by dashboard backend for caching
maxmemory 256mb
maxmemory-policy allkeys-lru
appendonly no
save ""
Directive Breakdown
DirectiveValueEffect
maxmemory256mbRedis will not use more than 256 MB of RAM. When exceeded, eviction kicks in.
maxmemory-policyallkeys-lruWhen memory is full, evict the least recently accessed key from any keyspace.
appendonlynoDisable Append-Only File. No write-ahead log. No durability guarantee.
save"" (empty)Disable RDB snapshots. No background saves to disk. Pure in-memory operation.
No Persistence
Redis holds no authoritative data. All cached values can be recomputed from PostgreSQL or Parquet files. A container restart clears the cache. Downstream services must handle cache misses gracefully.

Consumers

Backend (Express API)

The backend Express server connects to Redis via REDIS_URL=redis://vlthr-dashboard-redis:6379. Used for caching API responses to reduce PostgreSQL query load on repeated dashboard requests.

  • Connection: redis://vlthr-dashboard-redis:6379
  • Use case: Cache treasury data, trade lists, signal summaries
  • Cache invalidation: TTL-based or manual flush on new pipeline run
Pipeline

The pipeline orchestrator connects to Redis for ephemeral state coordination between pipeline runs. Stores transient data that does not need PostgreSQL durability.

  • Connection: REDIS_URL=redis://vlthr-dashboard-redis:6379
  • Use case: Cross-run state, deduplication keys, rate limiting counters
  • Depends on: Redis service started (no health check required)
Connection URL
Both consumers use the same connection string: redis://vlthr-dashboard-redis:6379. The hostname resolves via Docker's internal DNS on the vlthr-dashboard-net bridge network.

Notable Choices
  • No port exposed: Redis is only accessible within the Docker network. No host port mapping.
  • No health check: Redis Alpine is lightweight and reliable. The unless-stopped restart policy handles rare failures.
  • No volume for data: No persistence means no data volume needed. Configuration is the only mount.
  • Alpine image: Minimal footprint (~30 MB). Fast startup. No shell access for attack surface.
