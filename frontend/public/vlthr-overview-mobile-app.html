Data Ingestion

Bybit public REST feeds are pulled, enriched, and stored as Parquet. The pipeline consumes the enriched files.

OHLCV klines
  • Symbols: BTCUSDT, ETHUSDT, SOLUSDT, XRPUSDT, BNBUSDT (DOGEUSDT disabled).
  • Timeframes: 4h, 1h, 30m, 15m, 5m, 1m.
  • Output path: data/bybit/{SYMBOL}/{TF}/{YYYY}/{MM}.parquet.
  • Endpoint: GET /v5/market/kline, category linear.
Market data
  • Funding rate: 8h interval.
  • Open interest: 1h interval.
  • Orderbook L2: 100 levels snapshot.
  • Outputs: {SYMBOL}/funding_rate/, {SYMBOL}/open_interest/, {SYMBOL}/orderbook/.
Enrichment

Merges OHLCV with open interest and funding rate via merge_asof by nearest timestamp. No forward leakage.

Schema: timestamp, open, high, low, close, volume, turnover, open_interest, funding_rate.

12 portfolio gates
  1. Pre-flight: data freshness, circuit breaker, balance, calibration age.
  2. Scan + V2 filters: DQS, daily bias, volume, RSI momentum, regime, TP scale, BTC correlation.
  3. Ranker: minimum adjusted score >= 50.
  4. V7 Kelly veto: DQS >= 85 gets Kelly 0.
  5. Disabled symbols: DOGEUSDT blocked.
  6. Regime minimum DQS.
  7. Data quality gate: freshness + completeness + outliers >= 60.
  8. Correlation guard: max open positions, no duplicates.
  9. Trade count guard: daily and hourly limits.
  10. Directional balance: max same-side positions.
  11. Risk budget: Kelly-weighted risk vs ledger capacity.
  12. Calibration gate: Wilson lower bound >= per-symbol threshold.

Execution

Backend Express API, paper trade lifecycle, and auto-close monitoring.

Backend API
  • Container: vlthr-dashboard-backend on port 3002.
  • Trade monitor runs every 15 seconds against live parquet prices.
  • Routes: /api/paper/trade, /api/paper/trade/:id/close, VTC endpoints, AI engine proxy.
  • Google TOTP auth removed; dashboard opens directly.
Trade lifecycle

PENDING → OPEN → CLOSED. Pending trades expire after 90 minutes. Open trades close on SL_HIT, TP_HIT, TIME_EXIT, or LIQUIDATION.

Sizing and drift guards
  • Per-symbol margin cap: $1,667.
  • Max 2 open positions per symbol.
  • Entry drift guard rejects if market moves more than 0.3% from planned entry.
  • Risk ledger records dollar risk per trade.
Auto-close logic
  • Dynamic SL adjusts based on price trajectory.
  • Flash-wick guard uses bar-to-bar comparison, not entry price.
  • Time exit after max trade hours per symbol (12 to 48h).
  • Liquidation price computed with MMR = 0.5%.

Workflow Feedback

Status of global protocols and open issues. The WinSoftware folder was not found in the workspace.

PIVP — validation protocol

Strong gate discipline, but Python services lack a runnable unit/integration test suite. Phase 2 demands full test runs, which are currently manual. Add pytest coverage for gate logic, DQS scoring, and V2 filters.

GBEGP — build governance

Dev/prod separation is missing. There are no /development or /production directories and no .env.development or .env.production files. Environment detection should be automated at session start.

CCP — content and communication

UI copy rules should be audited across the existing dashboard. Existing strings may still contain banned marketing language or em dashes. Apply the style cheat sheet before any public-facing text goes live.

RODP — repository organization

File-length thresholds are exceeded: backend/src/server.cjs over 2,000 lines, pipeline/engine/portfolio_orchestrator.py over 1,700 lines, frontend/src/index.css over 2,500 lines. Docs and handoffs live in the repo root instead of /docs/memory. Make a migration plan rather than restructuring silently.

Pipeline gate audit

Twelve gates are well documented. The recent zero-signal bug showed V2 filters, freshness thresholds, and pre-flight bar age were too tight. Add a diagnostics endpoint that returns the first gate each symbol fails per scan.

Zero signal diagnosis

The workflow correctly orders checks from ingestion freshness to gate chain. Add automated regression tests for each root cause and a live dashboard widget that shows scan rejection reasons per symbol.

Open issues and next steps
  • Live paper trading is on a losing streak. Do not change parameters until the sample size and regime shift are audited.
  • Backtest assumes no slippage, no funding costs, and static crowding clusters. These are the most likely live divergence sources.
  • MR_BOOST = 3.0 may inflate mean-reversion position sizes during a drawdown.
  • Runtime tuning functions can overfit on a small live sample. Consider pausing them until 100 closed trades exist.
  • WinSoftware folder was not found. Provide its path so its workflows can be reviewed.

Audit reminder

Before changing any live parameter, confirm the losing streak is not a small-sample or regime issue.

  • Run a 30-day backtest with current parameters.
  • Compare live closed trades to backtest for the same period.
  • Check slippage, funding, and data freshness.
  • Review MR_BOOST and runtime tuning activation.
  • Locate and review the WinSoftware folder workflows.
